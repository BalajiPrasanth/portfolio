Security Engineer

Geelong, Victoria / Australia

I secure the layer where systems talk to each other. My work sits on the API gateway: writing and tuning the policies that decide which requests get through, enforcing OAuth 2.0 token flows at the edge, handling encryption and decryption of message payloads, validating HMAC signatures, and integrating and testing REST and SOAP services until they behave the same way under load as they do in a test console. Most of that has been in banking, where a rejected transaction and a leaked field are both incidents, so the habits matter more than the tooling: least privilege, defence in depth, verify every hop, and leave an audit trail somebody else can follow. I am a blue team engineer by instinct. I would rather instrument and harden a system than break it.

Selected Work

Five pieces of work that show what I actually do at the gateway.

Gateway Policy, Written to Hold

Policy design and rollout on CA Layer 7 for a core banking API estate: authentication, authorisation, rate limiting, schema validation and threat protection, assembled so that a change to one service did not quietly weaken another.

CA Layer 7 / Policy Manager / OAuth 2.0

Message Level Encryption

Encrypting and decrypting request and response payloads at the gateway so that sensitive fields stayed protected past the transport boundary, with key handling and rotation that did not depend on one person remembering to do it.

Payload encryption / Key rotation

Signature Validation

HMAC signing and verification on inbound and outbound traffic so that a message altered in transit could not be mistaken for one that was not, including the replay and timestamp checks that signature schemes usually forget.

HMAC / Nonce / Replay protection

REST and SOAP, Tested Properly

Integrating and testing services on both sides of the fence: WSDL driven SOAP endpoints and JSON REST APIs behind one gateway, with negative test cases for malformed payloads, bad tokens and oversized requests rather than only the happy path.

REST / SOAP / WSDL / Postman / SoapUI

Tokens and Access Control

Token validation at the edge rather than inside every service: checking issuer, audience, expiry and scope before a request goes anywhere, so a service could trust what reached it and an expired or borrowed token stopped at the gateway.

OAuth 2.0 / JWT / Scopes and roles
